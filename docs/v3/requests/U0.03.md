# Requests from U0.03

## R1 — Biome's silent stack overflow (U0.02 R1) has two more triggers; both are worked around in U0.03's paths

- **Where:** any file Biome 2.5.14 lints with `nursery/noFloatingPromises` on. Same symptom as `U0.02.md` R1: the native
  binary aborts, the launcher exits **0**, no `Checked N files` line. Found by reading the output, bisected with
  throwaway probe files (all deleted).
- **Trigger A — `Static<TRecord>`.** A type derived from a schema that holds a `Type.Record(...)` overflows as soon as
  another file makes Biome resolve it (`SandboxPolicy.env.set`, `RuntimeSnapshot.diagnostics`, the header and
  package-version maps of the host protocol). Remedy used: a helper with an EXPLICIT return type,
  `const stringMap = (): TUnsafe<Record<string, string>> => Type.Unsafe<Record<string, string>>(Type.Record(...))`.
  The emitted JSON Schema is unchanged.
- **Trigger B — an `await` whose value holds an `ErrorInfo` and is not bound to a name.** `await lab.run(request)` as a
  STATEMENT (value: `AgentExit`, which has `error?: ErrorInfo`), `f(await spawn(...))`, and
  `cond ? literal : await handleToolCall(...)` all overflow; `const exit = await ...` does not. Remedy used: bind the
  value, or await a `Promise<void>` wrapper (`Lab.complete`).
- **Affects:** every unit that writes `[S]` schemas with a record (`U0.04`, `U0.05`, `U0.07`) or awaits an `AgentExit`
  (`U1.06`, `U1.07`, `U1.09`). The tooling fix proposed in `U0.02.md` R1 (require the `Checked <n> files` line) is what
  would make this visible in every check; until then read the last line of the Biome output.

## R2 — DESIGN 3.3 names `HostEvent` and `SpawnRequestWire` without defining them

- **What U0.03 froze (smallest consistent reading):**
  - `SpawnRequestWire = SpawnRequest` (same schema object). Every member is JSON already and the child reads the prompt by
    reference (`readVerified(req.systemPrompt)`, DESIGN 3.4).
  - `HostEvent = { type; at; data }` for each of the eighteen `RuntimeEvent` types, `data` being that type's payload
    schema. The PARENT stamps `runId`, `agentId`, `incarnation` and the durability of the type; `seq` travels on the
    `event` frame. `runtime-contract` exports the table both are built from: `RUNTIME_EVENT_TYPES`
    (`{ durability, data }` per type) and `RUNTIME_EVENT_TYPE_NAMES`.
- **Proposed change:** two lines in DESIGN 3.3 saying so.

## R3 — the `ready` frame carries an `AttestationClaim`, not the literal-typed `Attestation`

- **Why:** DESIGN types `modelFallback: false`, `extensionsLoaded: 0`, `settings.compaction: false`… as literals, and
  PLAN U0.03 / U1.07 want `diffAttestation` to FLAG `modelFallback`. With the literals in the frame schema a child that
  fell back is refused by `decodeFrame` as "schema-violation at /attestation/modelFallback" and `diffAttestation` never
  sees it.
- **What U0.03 did:** `Attestation` is DESIGN's type, verbatim (schema + static type). `AttestationClaim` is the same
  shape with those members widened (`boolean`, non-negative integer, `string`); the `ready` frame carries the claim;
  `diffAttestation(expected: AttestationExpectation, got: AttestationClaim): AttestationMismatch[]` names every
  difference (`field`, `expected`, `got`); an empty list means the claim IS an `Attestation`. Every `Attestation` is
  assignable to `AttestationClaim`, so child code written against DESIGN typechecks.
- `AttestationExpectation` (not in DESIGN) is what the parent knows before the child speaks;
  `attestationExpectation(request, engine, effectiveSystemPromptSha256, platform)` builds it. `envAllow` =
  `sandbox.env.allow` ∪ the KEYS of `sandbox.env.set` (a variable the parent sets is visible in the child), then
  `envKeys ⊆ envAllow ∪ OS_INJECTED_ENV[platform]` with the PARENT's platform; a child reporting another platform is a
  mismatch of its own. Auth: subscription mode requires `oauth` + `subscription: true`; api mode requires `api_key`; an
  `api_key` without `allowApiKey` is always a mismatch.

## R6 — how a runtime package RUNS the conformance suite (information for U1.06, U1.07, U5.04)

```ts
import { runtimeConformance } from '@cohorte/runtime-contract/conformance';
runtimeConformance(factory, { modelProbe, seal, spawn?, boundMs?, quietMs?, label? });
```

- `factory({ bindings, script })` returns a FRESH `AgentRuntime` wired to the suite's `RuntimeHostBindings`; the suite
  closes it. `script: BrainScript = { turns: { text?, toolCalls?: { tool, input }[] }[] }`: model request k is answered by
  `turns[k - 1]`; a turn without tool calls ends the loop. The runtime under test arranges for its model to follow it
  (fake: translate to `FakeStep`s; Pi: faux-provider responses; fake brain: a script).
- `modelProbe({ runId, agentId, incarnation })` returns every recorded model input for that agent, oldest first:
  `{ systemPrompt, messages: { role: 'user' | 'assistant' | 'tool-result', text }[] }` (rules 10 and 12).
- `seal(text)` mints the `SealedText` of the suite's tool results: `sealedText` from `@cohorte/testkit`. It is an option
  because `runtime-contract` may not cast `as Sealed` (check-layers rule f).
- `spawn` overrides `role | model | auth | sandbox | thinking` of the suite's request: a runtime whose resolved
  endpoint is not `https://conformance.invalid/v1` passes its own `auth` here (rule 11 swaps the base URL itself).
- Granted tools: `conformance_echo`, `conformance_hold`; `conformance_not_granted` is scripted but NOT granted.
- Readings the suite fixes where DESIGN 2.2 is silent:
  - rule 1: the ungranted call must surface as EXACTLY ONE of `tool.call.rejected` (no handler) or
    `tool.call.requested` + handler (DESIGN 3.10 lets the fake hand any tool name to the host); `tool.call.requested`
    is emitted BEFORE `handleToolCall` runs; ordinals are gapless and `toolCallId === tc_<incarnation>_<ordinal>`;
  - rule 2 also validates every event against the `RuntimeEvent` schema and requires `agent.exited` to be the last
    event, with `exit.lastSeq` equal to its `seq`;
  - rule 3 re-spawns while the first incarnation is LIVE (held in a tool call);
  - rule 6 covers `systemPrompt`, `task` and `continuation.note`;
  - rule 9 closes a runtime whose agent is held in a tool call, then compares `process.getActiveResourcesInfo()`
    (`Timeout`, `ProcessWrap`) with the count taken before the factory ran, and checks `handle.process.pid` is gone;
    an unref'd timer is invisible to it;
  - rule 12 accepts the note as a second user message OR after `CONTINUATION_NOTE_SEPARATOR` (exported by the
    contract), requires `sha256(system prompt seen) === agent.spawned.effectiveSystemPromptSha256`, and plants two
    canaries in `context.entries` (an entry id, the content of a `source.ref` file) that must never reach the model.
- `checkConformance(factory, options)` returns one outcome per rule without registering tests (used by the teeth tests).
- A rule the runtime's `capabilities()` rule out (rule 4: no cancel at all; rule 5: `pause.toolBoundary: no`) is
  reported through vitest's `context.skip(reason)`.
