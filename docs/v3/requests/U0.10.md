# Requests from U0.10

## R1 (for U0.G) — `logs` and `tail` have a machine output but no `--json` document

- **Where:** `apps/cli/src/contract/verbs.ts` (`json` marker) and `apps/cli/src/contract/documents.ts`
  (`JSON_OUTPUTS`), against DESIGN 2.3.4 (`tail`'s result column: "NDJSON stream") and DESIGN 4.7
  (`logs|tail --follow [--since-seq N] [--replay K] [--format=line|json] [--ephemeral]`).
- **What fix round 1 changed:** `cli.ts` used to register `--json` on all 34 verbs while `JSON_OUTPUTS` covered 17,
  so the invariant the plan asks this unit to freeze ("every verb flagged `--json` has an entry in `JSON_OUTPUTS`")
  was false and nothing noticed. `VerbSpec` now carries `readonly json?: boolean`, `cli.ts` registers `--json` only
  for a verb that has it, and `json-outputs.test.ts` pins `{verb.name | verb.json}` equal to `Object.keys(JSON_OUTPUTS)`.
- **What U0.10 resolved on its own:** `discover` DOES have a document — DESIGN §9 says "`cohorte discover` prints
  the deterministic scan as a Project Model document" — so it is now `json: true` with
  `{ source: 'project-model', name: 'project-model' }` (`ProjectModel` from `@cohorte/project-model/contract`;
  `DocumentRef`'s project-model arm became a two-name union). 18 verbs are flagged, 18 `JSON_OUTPUTS` keys.
- **What is left for U0.G to rule on:** `logs` and `tail` are deliberately NOT flagged. DESIGN 4.7 gives an
  observer `--format=line|json` over a *stream* of event envelopes, not a single `[S]` document, and the protocol
  has no document for one. Either (a) confirm that reading — an observer's machine output is `--format=json`, and
  `JSON_OUTPUTS` stays the map of single documents; or (b) add an explicit NDJSON-stream marker to `VerbSpec`
  (e.g. `jsonStream?: DocumentRef` naming the per-line envelope schema) and flag both verbs with it. U0.10 did not
  invent (b) because it would add a contract field DESIGN does not name, and `apps/cli/src/contract/**` is frozen
  at G0. The Wave-4 unit that fills `commands/{logs,tail}/index.ts` is the one that would be surprised.
- **Affects:** U0.G, and the Wave-4 units owning `logs`/`tail`.

Recorded here because the verb table is frozen at G0. No action needed unless U0.G prefers the sub-verb spelling.

## Deviations from DESIGN/PLAN (informational, no action needed unless a reviewer disagrees)

1. **`scripts/build.ts` step 1 (`gen-schemas`) is soft.** `scripts/gen-schemas.ts` is `U0.G`'s deliverable and does
   not exist while U0.10 runs (Wave 0 is sequential and `U0.G` runs LAST). `build.ts` checks whether the file
   exists; if not, it logs a one-line notice and continues (embed-assets already treats a missing `schemas/` root
   as contributing zero files). Once `U0.G` lands the script, `build.ts` picks it up automatically — no edit
   needed. This is the literal mechanism that lets U0.10's own `check` (which runs `build.ts`) go green before its
   only listed dependency waits on nothing from `U0.G`.
2. **`apps/cli/tsdown.config.ts` needed `deps.alwaysBundle: [/^@cohorte\//]`**, not just `onlyBundle`/`onlyImport`.
   tsdown externalizes anything literally listed under the importer's `package.json` "dependencies" by default
   (ordinary bundler behaviour), and `apps/cli/package.json` (U0.01, frozen) lists every `@cohorte/*` package
   there — so without `alwaysBundle` they would have been left as unresolvable bare `@cohorte/*` imports in the
   published bundle. `<SCRATCH>/understand/toolchain.md §3` measured a prototype where this was "unnecessary";
   that prototype's `apps/cli/package.json` apparently did not declare the internal packages as dependencies. The
   real, frozen `apps/cli/package.json` does, so `alwaysBundle` is required here. No contract changed, only the
   tsdown config's own `deps` object (fully owned by U0.10).
3. **`apps/cli/tsdown.config.ts` has no explicit `banner`.** `src/cli.ts` already starts with `#!/usr/bin/env
   node`; tsdown auto-detects the shebang from the entry chunk, and an explicit `banner: { js: '#!/usr/bin/env
   node' }` produced a DUPLICATE shebang (`[DUPLICATE_SHEBANG]`, a `SyntaxError` at run time, not a build-time
   warning). Removed; the file notes why.
4. **`CliContext`'s heavy ports (`Controller`, `Observer`, `HostSpawner`, `Renderer`, `RuntimeProviders`,
   `OpenStore`) are U0.10's own invented shapes**, not lifted from a literal DESIGN interface (DESIGN 1.2/2.3.4
   describe their BEHAVIOUR, not a TypeScript signature for `apps/cli`'s own composition-root ports — PLAN PC-4
   assigns "CliContext ... (apps/cli, U0.10)" without a verbatim type). Picked the smallest shapes consistent with
   DESIGN 2.3.4 (`Controller.send` mirrors the inbox/start route) and DESIGN 4.7 (`Observer.follow` mirrors
   "durable events by sequence ... ephemerals by tailing the spool ... merge order (sequence, sub)"). `apps/cli/
   src/contract/**` stays read-only after G0 (PLAN §3 rule 7): `U4.01`/`U4.02` (which build the real `compose`/
   `host`/`observe`/`control` implementations against these ports) may find a shape needs widening — that goes
   through an integrator amendment, not a silent edit, and should be loud in that unit's own `notes` per PLAN's
   optimistic-scheduling rule (b).
5. **Every Wave-0 command-module stub (`commands/<verb>/index.ts`) answers with the SAME `configuration/
   phase-not-available` error** (via `notImplementedCommand`, which since fix round 1 throws a classified
   `CohorteError` carrying that code — see item 10 — instead of a bare `NotImplemented`), regardless of which verb
   it is. DESIGN §9 gives a couple of verbs a more specific "stubbed with a
   seam" description (`update --check`, `brainstorm` "rejects: phase not available", `run-tool`/`send` "rejected
   unless policy enables them") — none of that policy-aware behaviour exists yet (the policy engine and the real
   command modules are Wave 2/4/5 units), so every verb gets the same generic, honest "not implemented" stub for
   now. The registered VERB TABLE (names, sub-verbs, hidden `__host`, one driving `CommandType` per verb) is the
   part of DESIGN §9 that is actually frozen at G0; the per-verb BEHAVIOUR is not this unit's to build.
6. **`JSON_OUTPUTS`'s exact verb -> document mapping is U0.10's best reading of DESIGN 2.3.4's result column**,
   not a literal table DESIGN spells out per verb. `status`/`inspect`/`diff`/`doctor`/`auth`/`reconcile` map
   fairly directly; the ten inbox-routed mutating verbs (`pause`, `resume`, ... `run-tool`, `send`) and `run` all
   map to `command-result` (DESIGN 2.3.4's inbox-route result), with `run` additionally allowed `run-state` (an
   observer's own `--json` output once it starts following). A Wave-4 command unit that finds a verb's real
   `--json` output does not match its `JSON_OUTPUTS` entry should treat that as a finding against U0.10's
   contract, not silently diverge.

## Fix round 1 — what changed, and why (for the reviewer and for U0.G)

An independent reviewer found two blockers, two majors and four minors. All are addressed; nothing was argued away.

7. **`lazy.ts` loads verb modules from a frozen map of 34 LITERAL specifiers** (`COMMAND_MODULES`), not from
   `` import(`./commands/${verb}/index.ts`) ``. A runtime-computed specifier is invisible to rolldown: the built
   `dist/cli.mjs` kept the template and emitted no verb chunk, so the SHIPPED CLI could execute no verb at all —
   it tried to load a `.ts` file next to `dist/`. Rule g of `check-layers` is per FILE, so 34 `import(` in
   `lazy.ts` is still one lazy-load site. `commandModulePath` is deleted (nothing used it); an unregistered verb is
   now a `RangeError`, which is also what kept the path-traversal guard honest. New
   `apps/cli/test/registry/lazy.test.ts` pins the map against `VERBS` in both directions and against the files on
   disk; `packaging.test.ts` runs every verb through the BUILT bundle and asserts one chunk per verb under
   `dist/chunks/`.
8. **Main-module guards are `import.meta.main`** (node >= 24.2; `apps/cli` engines are `^24.16.0 || >=26.1.0`), not
   `` import.meta.url === `file://${process.argv[1]}` ``. npm installs a `bin` as a SYMLINK, so the hand-rolled
   comparison was false for every real install: `cohorte --version` printed nothing and exited 0. (It also broke on
   any install path with a space or a non-ASCII character — `import.meta.url` is percent-encoded, `argv[1]` is not.)
   Changed in `apps/cli/src/cli.ts`, `scripts/{build,pack-check,embed-assets,stage-publish,write-bundle-manifest}.ts`
   and `packages/runtime-pi/src/child/entry.ts`. The old comment claiming `import.meta.main` had to be avoided was
   unfounded: tsdown rewrites nothing about the entry's top-level code.
9. **`pack-check.ts` now runs the INSTALLED bin** (`node_modules/.bin/cohorte`), as the plan deliverable says
   literally, instead of `node node_modules/cohorte/dist/cli.mjs` — which is why finding 8 had been invisible. It
   also refuses an empty `--version` output, and runs `cohorte status` through the bin, refusing
   `Cannot find module` / `ERR_MODULE_NOT_FOUND` and any exit code other than the `configuration` class's 10.
10. **`cli.ts`'s unknown-throwable fallback is `configuration/unexpected`**, per DESIGN 2.8 ("Unknown throwables ->
    `<nearest class>/unexpected`"). It was `configuration/phase-not-available`, a REAL catalogue code of that class,
    which `toErrorInfo` therefore returned verbatim for every unexpected throw in every verb, for the life of the
    product — and which is what hid both blockers from this unit's own tests. To keep the stubs' answer deliberate
    rather than accidental, `notImplementedCommand` now throws
    `CohorteError(errorOf('configuration/phase-not-available', …))` instead of a bare `NotImplemented`: a
    `CohorteError` keeps its own classification through `toErrorInfo`. **Consequence a later wave should know:**
    running a verb through the real (non-fake) `CliContext` in Wave 0 now fails in `compose/index.ts`'s own
    `NotImplemented` stub and reports `configuration/unexpected: not implemented: compose` — that is the honest
    classification of an unbuilt seam, and it disappears when `U4.01` fills `compose`.
11. **`apps/cli/tsdown.config.ts` emits code-split chunks under `dist/chunks/`** (`outputOptions.chunkFileNames`),
    as DESIGN 1.4 step 3 says; `packaging.test.ts` asserts no non-entry file sits directly under `dist/`.
12. **`apps/cli/test/registry/version.test.ts` exists** (the comment in `cli.ts` had promised a file that did not).
    It reads `apps/cli/package.json` and fails if `COHORTE_VERSION` drifts from it, and asserts `--version` prints
    that same string; `verbs.test.ts` and `packaging.test.ts` no longer repeat the literal. The version stays a
    compile-time literal rather than a `BUNDLED_COHORTE_VERSION`/package.json read, so `--version` still touches no
    file on the one-shot start-up path (`francois.md`'s 10 s / 4 MiB budget) — the test is what binds the two.

## Fix round 2 — what changed, and why (for the reviewer and for U0.G)

A second independent reviewer found three majors and five minors, all of them about tests that pinned nothing
rather than about shipped behaviour (its `check` was green, and stayed green). Every finding is addressed;
none was argued away.

13. **`CommandArgs.options` carries ONLY `json`, and the contract now says so.** The registry is frozen and
    `cli.ts` registers no option but `--json`, so `allowUnknownOption(true)` leaves every other flag unparsed in
    `positionals`. A Wave-4/5 unit reading `args.options.wait` / `args.options.check` would have got `undefined`
    with no usage error and no type error. The doc comments on `CommandArgs.positionals` and `.options` state the
    invariant (`apps/cli/src/contract/command-module.ts`), R2 above is corrected, and a new
    `apps/cli/test/registry/args.test.ts` pins the delivered shape for a flag (`run spec-1 --wait 8 --detach
    --json` -> positionals `['spec-1','--wait','8','--detach']`, options `{json:true}`), for no flag at all
    (options `{}`), and for a sub-verb (`config get <key>` -> `subVerb: 'get'`, positionals `['<key>']`). It is a
    separate file because it mocks two command modules, which `verbs.test.ts` needs to stay real.
14. **`cohorte help` and `cohorte help <verb>` exit 0, not 2.** `help [command]` is advertised in the CLI's own
    `--help`, so it is a user-facing route that printed exactly what was asked. `commanderExitCode` allow-listed
    the code NAMES `commander.helpDisplayed` / `commander.version`, but commander raises `commander.help` for the
    `help` sub-command — and for the bare `cohorte`, where it IS a usage error. Only commander's own `exitCode`
    separates them (0 vs 1), so `cli.ts` now keys off that. `verbs.test.ts` pins `--help`/`help`/`help status` at
    0 and `cohorte` with no verb at 2.
15. **The verb registry's MEMBERSHIP is pinned against DESIGN §9, not against itself.** Every assertion derived
    its expectation from `VERBS`, so a coordinated deletion (the `VERBS` entry + its `COMMAND_MODULES` loader +
    its `commands/<verb>/index.ts`) left all tests green — on a table frozen at G0 that every Wave-4/5 unit builds
    on. `verbs.test.ts` now carries `DESIGN_9_VERBS` (34 names, transcribed by hand) and `DESIGN_9_SUB_VERBS`
    (`config get|set|validate|trust`, `auth login|status|logout`, `providers list|test`, `models list`,
    `spec validate|freeze`, `policy explain`) and asserts set equality in both directions, plus that `__host` is
    the one hidden verb.
16. **The build guard reads the REAL `apps/cli/tsdown.config.ts`.** It used to build a synthetic fixture against a
    hand-written `onlyImport: ['commander']`, proving only that tsdown's mechanism works in general — adding
    `@earendil-works/pi-ai` to the shipped cli entry left all 150 tests green, and `pack-check`'s `cli.mjs` grep
    only fires once a Pi import actually exists. `packaging.test.ts` now imports the config's default export
    (`tsconfig.tests.json` already includes `apps/*/*.config.ts`), pins both entries' allowlists against DESIGN 1.2
    net 4 verbatim, pins `deps.onlyBundle: []` on both, asserts no `@earendil-works/*` name in the cli entry, and
    feeds the REAL cli allowlist into the fixture build. Verified by experiment: with Pi added to the cli entry's
    `onlyImport`, two tests go red.
17. **The staged publish manifest is tested.** DESIGN 1.4 step 4 is an enumerated deliverable and had zero
    coverage: `pack-check` only asserts the tarball's top-level paths and that it installs. `packaging.test.ts`
    now reads `<out>/.publish/package.json` and pins the exact key set (`bin dependencies engines files license
    name repository type version`), the absence of `scripts`/`devDependencies`, `license: AGPL-3.0-only`,
    `files: ['dist','assets']`, the absence of any `@cohorte/*` dependency, that the dependency NAME set is exactly
    the union of the two `onlyImport` allowlists, and that every version is EXACT (no `^`/`~` — PLAN F-6: a caret
    on a 0.x Pi could install two `pi-ai` copies and break `instanceof ModelsError`).
18. **`define.__COHORTE_VERSION__` / `__ASSETS_TREE_SHA256__` are tested** (DESIGN 1.4 step 3's bundle <-> assets
    cross-check). They are substituted into nothing today — `apps/cli/src/assets/index.ts` is reachable from no
    bundle entry until Wave 4 wires it in — so a typo in a define key would have gone unnoticed for three waves.
    `packaging.test.ts` pins `__COHORTE_VERSION__` on both entries, and re-evaluates the config with
    `COHORTE_BUILD_OUT_DIR` set to the directory the test's own build used, asserting `__ASSETS_TREE_SHA256__`
    equals that build's `assets/manifest.json` `treeSha256` (a real 64-hex digest, never `'unknown'`).
19. **Two test-fidelity defects in `packaging.test.ts`.** (a) "one chunk per verb" matched by name PREFIX, so
    `run-tool-<hash>.mjs` satisfied `run`; it now matches the full hashed chunk name
    (`^<verb>-[A-Za-z0-9_-]+\.mjs$`). (b) `writeFileSync` was pulled in with a dynamic `await import('node:fs')`
    beside a static `node:fs` import in the same file; it is static now.
20. **Two `as unknown as TSchema` casts dropped** from `apps/cli/src/contract/documents.ts`. `TUnsafe<T> extends
    TSchema` and there is exactly one typebox install (the workspace override pins 1.3.7), so the escape hatch
    bought nothing and would have hidden a second typebox identity if one ever appeared. `tsc -b` is green without
    them; the file records what a future failure there would mean.
