## R9 — round 3 (this run): the `check-layers` rule-f violation fixed properly, plus a same-shaped bug it uncovered

An interrupted earlier run of this unit had left `packages/core/src/events/index.ts` casting
`redactor.sealJson(withRedactions).value as SealedEventDraft` — exactly the `as Sealed…` pattern rule f forbids
outside the redactor. The reason it was there: `Redactor.sealJson<T extends JsonValue>` cannot be called with
`T = EventDraft` at all — `EventDraft` (`@cohorte/persistence/contract`) is a discriminated union whose payload
includes `ErrorInfo` (`@cohorte/base`) for several event types (`agent.failed`, `pipeline.failed`, `error`, …), and
`ErrorInfo` is deliberately an `interface` there (self-referential `cause?: ErrorInfo`, and the file's own comment
notes Biome 2.5.14 overflows its stack trying to infer the `Static<>` call otherwise). TypeScript only grants an
object **type** (not an `interface`) the implicit string-index compatibility that `T extends JsonValue` needs, so
`EventDraft` — or anything containing it — never satisfies that bound, regardless of how the value reaching the call
is cast. This is a real, reproducible TypeScript limitation (confirmed on a minimal repro), not a mistake in `base`;
changing `ErrorInfo` to a `type` alias is not proposed (it would reintroduce the Biome stack overflow the comment
documents, and `base` is frozen). **No dependency change requested — worked around entirely inside this unit's own
paths:**

`packages/core/src/events/index.ts` now declares a local `DeepJson<T>` homomorphic mapped type (recurse into arrays
and objects, pass primitives/`undefined` through unchanged) and calls `sealJson` with `T = DeepJson<EventDraft>` (and
its pre-redactions variant). `DeepJson<X>` re-states `X`'s shape as fresh object-type literals — same field names,
same value types, nothing renamed — which TypeScript treats as JsonValue-compatible where the original interface-
bearing type is not, and which is mutually assignable to `X`. `sealJson`'s own generic parameter then mints the
literal `Sealed<EventDraft>` (`== SealedEventDraft`) this function returns; no cast to any `Sealed…`-named type
appears anywhere in the file (`node scripts/check-layers.ts` clean). Any later unit that needs to seal another
type containing an `interface` (not `type`) member — `ErrorInfo` is the only one produced by Wave 0 — can reuse the
same `DeepJson<T>` shape rather than reaching for `as Sealed…`.

The same investigation found a second, independent instance of the identical shape one file over:
`packages/core/src/durability/journal/index.ts`'s `createEffectJournal().run()` called
`tx.beginEffect(spec.intent)` with `spec.intent.request` / `.verify` still typed `JsonValue` (DESIGN 2.5's
`EffectSpec<R>.intent: Omit<EffectIntent, 'request'|'verify'> & { request: JsonValue; verify: JsonValue }`, this
unit's own `contract/internal.ts`) where `StateStore.beginEffect` needs a real `EffectIntent` whose `request` /
`verify` are `SealedJson` (`@cohorte/persistence/contract`) — the call was passing raw, un-redacted JSON into the
journal. This one needed no `DeepJson` trick: `request`/`verify` are already typed plain `JsonValue` (not a union
with `ErrorInfo` inside), so `deps.redactor.sealJson(spec.intent.request).value` alone is already `SealedJson` and
assembling `sealedIntent: EffectIntent = { ...spec.intent, request: …, verify: … }` before the transaction closed
both the type error and the missing redaction. No file this unit does not own was touched by either fix.

**Affects:** informational; no dependency change. A later unit implementing the real `Redactor`
(`packages/security/src/redact/seal.ts`, not yet on disk — still a Wave-0 `NotImplemented` stub in
`packages/security/src/redact/index.ts`) should be aware `sealJson` is called from `core` with a `DeepJson<T>`-shaped
generic argument, not the bare contract type, for any event/effect payload that nests `ErrorInfo`.
