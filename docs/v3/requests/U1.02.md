# Requests from U1.02 (security/decide/paths)

Nothing here asks for a contract change: `PathResolver`, `ResolvedPath`, `PathViolation` and `GlobMatcher` are
implemented with the signatures DESIGN 2.6.1 / 2.6.3 froze. These are the three points where DESIGN left a
choice, the reading this unit took, and what a consumer has to know.

## N1 — `GlobMatcher.isDenied` is a PERMISSION test, not a deny-set test (affects U2.01, U2.03, U2.04, U3.x)

`isDenied(relativePosixPath, grant, intent)` now means **"not permitted for this intent"**:

```ts
denySet(intent) matches  ->  true          // deny beats allow (DESIGN 2.6.3 step 7, "deny sets first")
allowSet(intent) does NOT match -> true    // fail closed (I2): a path in no allow set is not permitted
otherwise -> false
```

- **Why:** the contract takes the whole `AgentGrant` and not a `GlobSet` — `matches(path, set)` already exists
  for a bare set test. Step 7 says "deny sets first", which presupposes both sets. With the narrow reading
  (deny sets only) the plan's own listed test row "deny beats allow" was unwritable at this layer, and output
  filtering (`search`, `list_files`, `git_diff` in U2.03) would have leaked files belonging to another surface
  in the same worktree, where the gate's allow stage never runs (I11).
- **Consequence for callers:** `isDenied === false` is a full permission answer for the path layer; you do NOT
  need a second `matches(path, grant.read)` call. An empty `read`/`write` GlobSet permits **nothing**, so build
  a grant with real allow globs in tests — a fixture grant with empty allow sets now denies everything.

## N2 — `symlinks: 'allow'` lifts the per-component check, not the final containment (affects U2.09, U3.04)

DESIGN 2.6.3 step 3 makes `allow` skip the "the target must stay inside a root" test *per component*; step 4
then tests containment of the final canonical path, with no exception for the mode. This unit reads it that
way: `resolve()` never returns an ok result whose `canonical` lies outside every root, in any mode.

- A chain that hops out of the roots and back into one is allowed under `allow` and refused under
  `deny-outgoing` (that is the whole difference between the two modes); a chain that ends outside every root
  is `outside-roots`.
- The reason is not purity: an ok result outside the roots cannot carry an honest `root`/`relative` pair, and
  `relative` would have to climb with `..`, which no `**` pattern matches — that is exactly the defect fix
  round 1 closed (D-1 below).

## N3 — step 1 hygiene: `~` is a SEGMENT rule; `$` is still refused anywhere

- `~` is refused when a path segment IS the home shorthand (`~`, `~user`), not when a name merely contains a
  tilde: `notes.txt~`, `a~b.ts`, `~report.docx` resolve.
- `$`/`${...}`/`%VAR%` are still refused **anywhere** in the input (unchanged). A real-world casualty is the
  Office lock file `~$report.docx`, refused by the env-syntax rule. If a later unit needs those names,
  narrowing the env rule is a DESIGN question, not this unit's call — a test pins the current behaviour.
- The 4096 limit is now measured in UTF-8 **bytes**, as its own message always said.
