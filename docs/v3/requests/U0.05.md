# Requests from U0.05

Nothing here blocks U0.05 (its check is green). These are the points where DESIGN was silent, where U0.05 chose the
smallest consistent reading, or where another unit is affected.

## R1 — `Type.Pick` on a large object crashes Biome (same defect as U0.02 R1), and a crashed Biome still exits 0

- **Where:** `packages/protocol/src/documents.ts`, `ProjectRunSummary` (the row of `ProjectStatusDocument.runs`).
- **What happened:** with `export const ProjectRunSummary = Type.Pick(RunNode, [...])` (inferred type), `biome ci` overflowed
  its stack in EVERY file that names the const (first seen in `test/catalogue/documents.test.ts`), printed no
  `Checked N files` line and exited 0 — so U0.05's literal check command was "green" with nothing linted and one test
  file unformatted. Destructuring `RunNode.properties` into a new `Type.Object` crashed the same way.
- **What U0.05 did:** remedy (a) of U0.02 R1 — an explicit annotation: `export const ProjectRunSummary:
  TUnsafe<ProjectRunSummary> = Type.Unsafe<ProjectRunSummary>(Type.Pick(...))`, with `type ProjectRunSummary =
  Pick<RunSnapshotDocument['run'], ...>` exactly as DESIGN 2.3.5 writes it. `biome ci packages/protocol
  fixtures/schema-compat` now ends with `Checked 132 files`.
- **Still open (tooling, owner U0.01 / the lead):** the guard proposed in U0.02 R1 (lint is green only if the output has
  `Checked <n> files` and no `overflowed its stack`). Until then every unit must READ its Biome output.
- **Affects:** any unit that writes `Type.Pick` / `Type.Omit` / a projection over a big TypeBox object and exports it.

## R2 — `command.*.type` and `CommandResultDocument.type` are an OPEN enum over `COMMAND_TYPES`

- DESIGN 2.3.3 / 2.3.5 write `type: CommandType`. DESIGN 2.3.2 says a MINOR may add commands; a closed enum there would
  make every new command a MAJOR of the events schema. U0.05 authored `OpenEnum(COMMAND_TYPES)`: the writer-side
  validator still refuses an unknown command, the published schema lets a reader meet a later one. Static type:
  `OpenEnumOf<CommandType>`.

## R4 — `InspectDocument` artifact cap, as schema

- `bytes` has `maximum: INSPECT_ARTIFACT_MAX_BYTES` (3 MiB); `content` has `maxLength:
  INSPECT_ARTIFACT_MAX_CONTENT_LENGTH` = `4 * ceil(cap / 3)` = 4 194 304, the base64 length of the byte cap, which also
  bounds utf8 content (never more characters than bytes).
- **Information for U4.x (inspect verb):** a base64 window of the full 3 MiB is therefore 4 MiB of characters BEFORE the
  rest of the document, which is over the "4 MiB one-shot client" of DESIGN 2.3.4. The schema cannot express "3 MiB if
  utf8, less if base64" without `if/then`; the printer should cap a base64 window at about 2.9 MiB of bytes.
- `InspectDocument` is a `Type.Union` of eight CLOSED objects that each repeat the four header fields, not the
  intersection DESIGN writes: the members of an `allOf` cannot be closed (U0.04 R1 rule 2).
