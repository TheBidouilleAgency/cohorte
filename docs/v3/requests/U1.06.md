# Requests from U1.06

## R1 — DESIGN 3.10 leaves six points of the fake open; what U1.06 froze (information, amend DESIGN if another reading is wanted)

- **`match.attempt` is not a `SpawnRequest` field.** DESIGN 2.5 (`retrying`) says a retry's request is byte-identical apart
  from `incarnation`, so nothing in the request says "attempt 2". The fake DERIVES it from the requests it has accepted
  for `(runId, agentId)`: a spawn with `continuation === null` opens an attempt, a spawn with a continuation belongs to
  the current one (DESIGN 2.2.3: "a later incarnation of the same attempt"). Still request fields only, no phase (R10).
- **An absent `match.incarnation` means `'any'`** (an absent field never constrains). The FIRST matching rule wins, so
  "incarnation 1 crashes, 2 finishes" is two rules in that order, or one specific rule before a catch-all.
- **How a flat step list becomes turns.** A turn = one model request + one assistant message (`say`/`think`) + its tool
  calls. `model-request` opens a turn explicitly; otherwise one opens before the first content step and again when text
  follows a tool call. A `model-request` is only SENT when the next step needs it, so `model-request{status:429}` followed
  by `fail{...}` is ONE failed request (`model.responded` with `httpStatus`, `stop:'error'`, `error`).
- **`usage` sets the tokens of the NEXT model request** (merged over `defaults.usagePerTurn`; `total` defaults to the sum).
- **`tool` never yields `tool.call.rejected`:** every scripted call, granted or not, reaches the real ToolHost. That is the
  point of "`tool` is ANY string" (the host's gate is what is under test). `submit` calls the grant with `terminal: true`
  (`submit_result` when there is none). `expect` that does not hold = exit `failed` / `configuration/unexpected`.
  `onDenied` runs when the result `isError`.
- **Endpoint (conformance rule 11).** The fake has no endpoint of its own. `createFakeRuntimeProvider({ script, baseUrl })`
  makes it answer for one (rule 11 then holds, and the conformance run sets it); WITHOUT `baseUrl` it accepts the endpoint
  its plan pinned. Chosen so that Wave-1 units already coding against the U0.03 stub `{ script }` are not refused with a
  security error by a default they could not know. If the lead prefers strict-by-default, it is a one-line change plus a
  constant; say so before G1.
- **`sandbox.require: 'os'` is NOT refused.** An in-process brain has no process to confine and cannot execute anything
  (C1); it reports `isolation.level: 'none'`, `backend: 'in-process'` on `agent.spawned` and `no` on the four isolation
  capabilities. The host decides what to do with that.
- **Affects:** U1.09 / U1.INT (skeleton), every later test that scripts the fake.

## R2 — `RuntimePin.artifacts[].role` has no value for "a script", so the pin names the script as its engine

- **Where:** DESIGN 2.2.7 (`role: 'agent-host-bundle' | 'engine-package-tree' | 'install-lock'`) against DESIGN 3.10
  ("`pin()` hashes the script"). A script given as a VALUE has no path either.
- **What U1.06 did:** `engine: { name: 'fake-script', version: 'sha256:<canonical script hash>' }`, `artifacts: []`,
  `digest = sha256(canonicalJson(the rest))`. `create()` recomputes it and fails `security/runtime-pin-mismatch`.
  `runtimePinning` is declared `partial` (the pin covers the script, not the installed code).
- **Proposed change:** none required; optionally a fourth role `'script'` with an optional `path`.

## R3 — no catalogue code for an invalid fake script

- **Where:** `@cohorte/base` catalogue (append-only, not U1.06's). `parseFakeScript` / `validateFakeScript` /
  `createFakeRuntimeProvider` report a script that is unreadable or off-schema as `configuration/unexpected` (with the
  first five schema problems in `details.problems`), which is meant for unclassified failures.
- **Proposed change:** append `configuration/fake-script-invalid` (not retryable); U1.06's three call sites are in
  `packages/runtime-fake/src/script/parse.ts` (`invalid()`), one line.

## R4 — Biome's silent stack overflow (U0.02 R1, U0.03 R1): one more trigger, and `unit:check` still reports `biome ok`

- **What happened:** `unit:check U1.06` printed `biome ok (3 path(s))` and GREEN while three owned files had never been
  linted or formatted (Biome aborted, exit 0). Found by reading the output of a manual `biome check`.
- **Trigger C (new):** an expression STATEMENT whose type returns itself — `builder.agent(...)` on the fluent
  `FakeScriptBuilder`, not bound to a name. Remedy: bind it (`const extended = builder.agent(...)`).
- **Trigger B again:** `await promise.catch(() => {})` as a statement, where the promise is a `handleToolCall` result.
  Remedy: a `Promise<void>` wrapper. Every awaited `AgentExit` in U1.06's tests is bound or goes through
  `rig.complete()` (resolves with nothing).
- **Proposed change (tooling, U0.01's paths):** the guard U0.02 R1 asked for — the lint step is green only when the output
  has `Checked <n> files` and no `overflowed its stack`. U1.06 verified its own paths file by file.
- **Affects:** every unit; U1.07 / U1.09 will await `AgentExit`s too.

## R5 — the `[S]` schema of the script is exported as `FakeScriptSchema`

- **Why:** `FakeStep` is a recursive union; a TypeBox const that shares its name with a recursive type is the U0.02 R1
  overflow. The U0.03 stub's interfaces (`FakeScript`, `FakeAgentRule`, `FakeStep`) are kept verbatim as the static types;
  a compile-time assertion keeps the schema and the interface mutually assignable.
- **For `U0.G` / `gen-schemas`:** if `schemas/fake-script.schema.json` is wanted, the source is
  `@cohorte/runtime-fake/script` -> `FakeScriptSchema` (strict: a typo in a hand-written script must not pass as a no-op).
