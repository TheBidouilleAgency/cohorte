registry and the state-machine tables are **read-only for a unit**: a unit that believes one is wrong writes
`docs/v3/requests/<unitId>.md` and continues against a local adapter (PLAN §3 rule 7).

## 2. Decisions taken at this gate

### G0-D1 — `pipeline/guards` is an area subpath like the twenty others (closes U0.08 R2 / R10 item 2)

`packages/core/src/pipeline/guards/index.ts` (U0.09) held guard predicates but not the thin
`export { createPipelineGuards } from '../../contract/factories.ts'` every other area file carries, so
`@cohorte/core/pipeline/guards` was the one area subpath that did not publish its own factory and the frozen
barrel had no line for it.

**Decided:** add the re-export beside the predicates and give the barrel its line. Nothing was rewritten —
the predicates are untouched, the factory body stays the `NotImplemented` seam in `contract/factories.ts`,
and `U2.05` fills the directory without touching a barrel. `packages/core/test/contract/barrel.test.ts` now
covers twenty-one areas instead of twenty, so the invariant holds without an exception.

Files: `packages/core/src/pipeline/guards/index.ts` (U0.09), `packages/core/src/index.ts` (structural),
`packages/core/test/contract/barrel.test.ts` (U0.08).

### G0-D2 — `@cohorte/core/agents` exists, and publishes the attempt rule (closes U0.09 R1)

`ATTEMPT_CONSUMING_EDGES` and `attemptConsumed` (DESIGN 2.5.4, the rule behind
`agent.state.changed.attemptConsumed`) lived in `agents/lifecycle-table.ts` and reached nothing outside
`@cohorte/core`: the package maps `./*` to `./src/*/index.ts` and `src/agents/` had no `index.ts`, while the
barrel re-exported `./agents/lifecycle.ts` alone.

**Decided:** option (1) of the request — new `packages/core/src/agents/index.ts` re-exporting BOTH files, and
the barrel line changed from `./agents/lifecycle.ts` to `./agents/index.ts`. One definition, two spellings
(`@cohorte/core` and `@cohorte/core/agents`), no deliverable dropped. `U2.06` and `U3.03` read the rule as
data. Option (2) — moving the two names into U0.08's file — was rejected: it deletes a delivered, tested file
for no gain.

### G0-D3 — five `conflict/*` codes added to the error catalogue (closes U0.09 R2)

`COMMAND_MATRIX` rejects with `conflict/run-halted`, `conflict/use-retry`, `conflict/use-resume`,
`conflict/use-resume-ack` and `conflict/run-blocked`; none had a catalogue row, so nothing could print the
impact and remediation DESIGN 2.8 promises. The catalogue is append-only, so adding is the cheap direction.

**Decided:** five rows appended to the `conflict` block of `packages/base/src/catalogue.ts` (before the
`conflict/unexpected` catch-all), each with the impact and the remediation that names the way out, and the
five codes added to the hand-mirrored `NAMED_IN_DESIGN` list of `packages/base/test/errors.test.ts`. Nothing
was renamed; `ErrorCode` grew by five members. **This is a DESIGN 2.8 amendment**: the five rows are not in
DESIGN's table.

Files: `packages/base/src/catalogue.ts`, `packages/base/test/errors.test.ts` (both U0.02).

### G0-D4 — `logs` and `tail` keep `--format=json`, not `--json` (closes U0.10 R1)

Option (a) of the request is confirmed. DESIGN 4.7 gives an observer `--format=line|json` over a **stream**
of event envelopes; the protocol has no single `[S]` document for one, and `JSON_OUTPUTS` is the map of
single documents a verb prints. Option (b) — a `jsonStream?: DocumentRef` marker on `VerbSpec` — would add a
contract field DESIGN does not name to a table frozen at this gate, to describe something `events.schema.json`
already describes line by line.

**For the Wave-4 units that fill `commands/{logs,tail}/index.ts`:** the machine output of those two verbs is
NDJSON, one `events.schema.json` envelope per line, selected by `--format=json`. They are the only two verbs
with a machine output and no `JSON_OUTPUTS` entry, and that is deliberate. No code change.

### G0-D5 — `schemas/**` is excluded from Biome

Biome formats JSON, and its formatter disagrees with `JSON.stringify(…, null, 2)` (it collapses short arrays
onto one line), so `biome ci .` and `gen-schemas --check` each claimed the same bytes and one of them had to
be red. `schemas` joins `tsconfig.checks` in `biome.json`'s exclusion list: both are generated directories
whose generator owns their bytes, and `gen-schemas --check` is the authority that they are correct.

File: `biome.json` (structural).

### G0-D6 — `apps/cli/src/index.ts` stays the placeholder it is (closes U0.01 R4 item 1)

U0.01 offered the G0 integrator the option of dropping `apps/cli/src/index.ts` (`export {}`) and its `.`
export now that `src/cli.ts` exists. **Kept**: `scripts/test/resolve-edges.test.ts` (U0.01) requires every
package of `layers.json`, `cohorte` included, to have a `.` export pointing at an existing `src/index.ts`,
and nothing imports `cohorte` by name — the app is reached through its `bin`. Removing it would change
`apps/cli/package.json` and a passing structural test for no gain.

## 5. Two flakes fixed, because a gate that passes two runs in three is not passed

`pnpm verify` failed about one whole-tree run in three, on two different timing-sensitive tests, each of
which passes on its own three times out of three. Both were races in the TEST, not in the implementation;
both are fixed with the smallest change that removes the race and weakens no assertion.

1. **`packages/security/test/exec/lifecycle.test.ts`** — "the PidRegistry records the group while it runs".
   `createExecutor` records the pgid only AFTER `processStartToken` (which spawns `ps`), so a program that
   wrote once and exited could deliver its only chunk before the entry existed and the sample came back
   empty. The program now keeps writing for 400 ms and the FIRST NON-EMPTY sample is kept — a non-empty
   sample can only be taken between `record` and `remove`, which is exactly what the test asserts.
   **For `U1.04`:** nothing in `src/` changed; if you would rather record the group before the token probe,
   that is a design choice this gate did not make for you.
2. **`packages/testkit/src/fake-brain/child.ts`** — the 2 MiB stderr flood is written to a pipe, i.e.
   asynchronously, so the whole turn could finish before the parent had read past its 1 MiB incarnation cap
   and the truncation notice never existed. The child now waits for `process.stderr.writableLength` to reach
   zero before sending `hello`, so everything after that line happens with the cap already crossed. **Fix
   round 1:** that wait is bounded to 5 s and then carries on. It runs before `listen()` is installed, so a
   parent that does not drain stderr (or one whose own cap makes it stop reading) would have wedged the child
   there and turned a real assertion failure into an opaque timeout; with the bound, the parent's assertion
   still fails loudly if the cap was not crossed.
   **For `U1.07`:** the flood is now deterministic; `parent-fake-brain.itest.ts` was not touched.
   `pnpm --reporter=silent unit:check U1.07` is GREEN after the amendment.

Verified: four consecutive whole-tree `vitest run --project unit --project integration` runs, 151 files,
green, after the fix (three of four were green before it, which is the point).

## 8. The exit check

```sh
export COHORTE_CHECKPOINT_DIR=<absolute dir outside the repository>
pnpm --reporter=silent verify && node scripts/schema-compat.ts --self && node scripts/build.ts --out .build/gate-0 && node scripts/pack-check.ts .build/gate-0 && node scripts/checkpoint.ts G0
```

Run whole, in one shell, on a quiet tree. The environment variable is not decoration:
`scripts/checkpoint.ts` refuses to run without it (a checkpoint is never written inside the repository,
`docs/v3/workspace.md` §Commands), so the last step exits 2 in a shell that has not exported it. The `check`
string in `docs/v3/plan.json` omits it and is red for that reason alone — see `docs/v3/requests/U0.G.md` R5.

**`export` on its own line, never a variable PREFIX on the list** (fix round 2, reviewer finding 1). A POSIX
assignment prefix scopes the variable to the ONE command it prefixes, so
`COHORTE_CHECKPOINT_DIR=<dir> pnpm --reporter=silent verify && … && node scripts/checkpoint.ts G0` gives the
variable to `pnpm` alone and the last step still exits 2 — the exact failure this paragraph exists to
prevent. The spelling printed above was measured, whole, in one `zsh`. The other correct form, for a `check`
string that must stay one line and say what is missing rather than fail late, is
`… && COHORTE_CHECKPOINT_DIR="${COHORTE_CHECKPOINT_DIR:?set an absolute dir outside the repository}" node scripts/checkpoint.ts G0`
(that one IS a prefix on the single command that needs it).

## 9. Amendments after review round 1

An independent reviewer read the freeze. Four findings were fixed; one is the lead's.

1. **Every published schema is addressable by a golden instance** (major). `schemaNameForFixture` resolved a
   `document.<name>` fixture against `DOCUMENT_NAMES` — the seven protocol documents — so fourteen of the
   twenty-three schemas could never have a golden instance, `agent-output` among them (one of the six of
   spec 4, and a schema the AC-07 client reads); dropping `document.agent-output.json` into
   `fixtures/schema-compat/3.0.0-dev/` made `--self` RED with "no schema is named by this file name", and

## 10. Amendments after review round 2

A second independent reviewer read the freeze and the round-1 amendments. Every step of the gate was already
green; what he found was one command spelling this record published as authoritative, one hazard in another
unit's file, and two small overclaims.

1. **The exit check §8 published was itself broken on its last step** (major, and the one that mattered:
   §9 item 5 "fixed" it by printing the variable as an assignment PREFIX). A POSIX/zsh assignment prefix
   scopes the variable to the ONE command it prefixes, not to the `&&` list, so
   `COHORTE_CHECKPOINT_DIR=<dir> pnpm --reporter=silent verify && … && node scripts/checkpoint.ts G0` hands it
   to `pnpm` and `checkpoint.ts` still exits 2 — the exact failure §8's own paragraph exists to prevent. The
   reviewer reproduced it verbatim (`pack-check: OK (…)`, then
   `checkpoint: COHORTE_CHECKPOINT_DIR is not set`, `EXIT=2`) and confirmed that `export` on its own line
   makes the same step print `checkpoint G0: 77 tracked change(s), 815 untracked file(s)` and exit 0.
   **Fixed:** §8 now prints `export …` on its own line, and says why the prefix form is wrong. The first
   "Proposed change" of `docs/v3/requests/U0.G.md` R5 — which carried the same broken spelling to the lead,
   for `U1.INT` too — is deleted; only the `${COHORTE_CHECKPOINT_DIR:?…}` form remains, which IS a prefix on
   the single command that reads it and is therefore correct for a one-line `check` string in `plan.json`.

   `scripts/gen-schemas.ts` made it live, so from Wave 1 on a unit's private `build.ts --out .build/<unit>/`
